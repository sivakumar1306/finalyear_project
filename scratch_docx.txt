Adaptive Women's Health Engine

1.  Introduction

The Adaptive Women’s Health Engine (AWHE) is a proposed intelligent module for the SUNDR Smart Ring ecosystem that provides health and wellness insights regarding the menstrual cycle, based on physiological measurements continuously acquired by the ring’s sensors.

Unlike existing menstrual tracking apps that make predictions based on cycle dates, AWHE uses both physiological and calendar information to predict the user’s cycle and provide more accurate, personalized estimates of her menstrual status.

The AWHE is a decision support system that uses information from the wearable sensor to predict the body’s physiological state, and thereby improve confidence in health and wellness predictions related to the menstrual cycle.

2.  Problem Statement

Most current period tracking apps predict the next menstrual period based only on two factors:

• the date of the last period

• average cycle length

The first is intuitive, while the second (although rarely discussed) reflects the assumption that cycles are generally regular. However, it is common for women to experience irregular cycles length due to shifts in hormones, stress, illness, sleep patterns, recovery, or other factors.

Since the SUNDR Smart Ring constantly tracks the body’s vital signs and symptoms, this data can be used to more accurately determine the user’s current physiological state prior to ovulation and menstruation.

3.  Physiological Basis

Hormonal variations that occur throughout the menstrual cycle can have an impact on numerous variables. AWHE does not suggest that the use of wearables causes these variations. Rather, wearables are utilized to track these physical indicators, which provide information about the body’s internal hormonal condition.

Pipeline stages

The system comprises of the following components:

Smart Ring Sensors: continuously capture skin temperature, heart rate variability, resting heart rate, sleep, stress, and activity;

Data Preprocessing: perform data cleaning and normalization of the acquired signals;

Phase Estimation Engine: apply physiological rules to extract the probability distribution of the current phase;

Menstrual Prediction Engine: combine the information from the previous step with the cycle history (when available) to predict the date of the next period;

Confidence and Explainability: assess confidence scores and provide support for the prediction in terms of physiological basis;

Mobile: deliver the prediction and the confidence score within the SUNDR mobile application to the user.

6.  Rule-Based Physiological Phase Estimation

The first version of the engine uses a rule-based physiological analysis approach. Rather than immediately predicting the next period, the engine first estimates the user's current menstrual phase, then uses that estimate as input to prediction. Each rule below contributes evidence toward the most likely physiological phase.

Rule 1

Skin Temperature ↑

HRV ↓

Resting Heart Rate ↑

→  Estimated Phase = Late Luteal

Rule 2

HRV ↑

Resting Heart Rate ↓

Temperature Stable

→  Estimated Phase = Follicular

Rule 3

Temperature begins rising

Resting Heart Rate begins increasing

→  Estimated Phase = Ovulation

9.  Future Enhancement

The first solution implements a transparent rule-based decision engine because it is explainable and can be implemented right away.

As more anonymized smart ring data becomes available, the same framework can be used to implement more personalized supervised machine learning models (e.g., Random Forest, XGBoost, and LSTM) in the future.

10.  Conclusion

The Adaptive Women’s Health Engine represents the implementation of a physiology-based approach to menstrual health tracking within the SUNDR ecosystem. By virtue of its ability to estimate the user’s current cycle phase (given wearable physiological data) as input to predictions about the future, it is likely to offer significantly more accurate, explainable, and adaptive modeling than the simpler option of relying on data from the menstrual calendar.

The rule-based engine is a good choice for now because the current application needs such a solution to be immediately functional.

In the future, if and when there emerges a sufficient quantity of relevant data to begin training the machine learning version of this engine, switching to a machine learning model would be desirable.
